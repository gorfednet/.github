# Ship bot incidents

One dated line per incident whose cause was a pattern: what happened, what changed, a link.

- 13 November 2026: the owner's GitHub REST quota (5,000 an hour) ran out at about 09:03 ET and stalled ship-bot and every session until 09:23 ET (it had also run out on 10, 11 and 12 November). Ship-bot shared that quota through `gh auth token` and polled 21 repositories every 2 minutes with uncached REST, re-running the three gate scripts on every waiting pull request each pass. Changed: conditional requests with an ETag cache, gate answers reused while their inputs are unchanged, a stop under 200 remaining with one ntfy alert, and a GitHub App token with its own quota (plan row 1.3, PR on branch `fix/ship-bot-quota`).
- 13 November 2026, after PR 143 was installed: the quota ran out again at about 10:00 ET. Desk's lead was that sessions' `gh run watch` (3 s default) and `gh pr checks --watch` (10 s) were the main consumers. The numbers support it. The installed bot's warm passes charge 5 calls each (37 of 42 answered 304), about 150 an hour, or 3%. Between 10:23 and 10:39 ET the account spent 1,401, a pace of about 5,250 an hour, so sessions spent about 97%. One `gh run watch` at 3 s makes about 40 calls a minute, about 2,400 an hour. Before PR 143 the bot's share was about 1,800 an hour (36%). Changed: `--interval 60` in `~/.claude/rules/shipping.md` (Desk). The bot moves to its own quota when the GitHub App is installed.
- 13 November 2026: blackpixelrecords.com 29 and gorfed.net 140 were the first unattended deploys of their rows, and both failed with their rollbacks. Each row lacked something a deploy from the owner's clone gets for free. blackpixel had no `envFiles`, so the cleaned workspace had no `.deploy-env` and `site-deploy.sh` stopped on "SITE is required". gorfed.net set no `WORK_CONTENT_DIR`, so `/work/` built from the committed fixture and `deploy.sh` refused it. The owner's career-portfolio clone was on a drain branch whose content fails the build, so the row now syncs career-portfolio main as a sibling and takes only the gitignored archive staging from the owner's clone. Changed: both rows (`patches/2026-11-13-deploy-blocks.json`), and `patch-config.mjs` so a reviewed row edit reaches the live config without a session reading it (plan row 2.1).
- 13 November 2026: papers.4thcltr.com 35 merged, then its `verify` setup step (`make verify`, the full Playwright suite on this Mac) failed 7 of 144 specs at 16:33 UTC, all frame-timing wordmark specs, with the 1-minute load at about 11 on 10 cores. The same specs pass at normal load. A setup failure blocks the repository. Changed: a deploy row can say `"needsHeadroom": true`, and ship-bot then holds its merges while the load is above the core count (or can't be read), with a log line, no comment and no block. The papers row has it.
- 13 November 2026, 18:50 ET: the gate commands on PATH (`review-status`, `assert-checks-started`, `check-closing-keywords`) run from the detached worktree `.claude/worktrees/gates-main`, which was set to .github 143 that morning and never advanced. After .github 163 merged, the stale `review-status` read `not-run` on clean reviews, and a session labelled .github 164 over a blocking finding. Desk advanced the worktree by hand to 250f176. Changed: ship-bot fetches and moves `gates-main` to origin/main after every merge to .github main (refusing and sending ntfy when it has uncommitted changes), and each gate wrapper warns on stderr when its checkout is behind the last fetched origin/main (`lib/gates-worktree.mjs`, `scripts/gates/test/gate-env.test.sh`, plan row 1.7 follow-up).
- 13 November 2026, about 19:00 ET: `install.sh` passed its tests, then `launchctl bootstrap` failed with "Bootstrap failed: 5: Input/output error" and left ship-bot unloaded until Desk bootstrapped it by hand. `bootout` is asynchronous and the bootstrap ran before launchd had removed the old job. Changed: `launchd-load.sh` waits (up to about 10 s) until `launchctl print` no longer finds the job, bootstraps, retries once, and exits non-zero with a clear message when the agent is not loaded at the end (`test/launchd-load.test.mjs`, PR 166).
- 13 November 2026: ops 62, 74, 76 and 77 sat labelled and stuck ("required checks never appeared: review / review", from 12:10 to 19:25 ET on 76). The ops row expected the reviewer workflow's `review / review` check, which attaches only when a pull request opens or leaves draft; one review on open and then a `claude review` comment is deliberate, so a later push never gets it. Changed: the ops row expects no check (the verdict is `review-status`), and the config validator refuses any expected check named `review / …` and allows an empty list only with `claudeReview: true`; a repo with no expected checks runs `assert-checks-started --min-runs 0`, because a head pushed after ready has no workflow run at all (`patches/2026-11-13-ops-expected-checks.json`, `test/config.test.mjs`).
